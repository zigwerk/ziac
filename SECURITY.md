# Security Policy

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability, leaked credential or
unsafe deployment path. Use GitHub private vulnerability reporting on the
affected repository. If that is unavailable, contact the organisation owners
through the private contact listed on the Zigwerk GitHub profile.

Include the affected version or commit, impact, reproduction steps and any
known mitigation. Never include live credentials or customer data.

We will acknowledge a complete report as soon as practical, coordinate a fix
and disclosure, and credit reporters who want attribution.

## Supported Versions

Before the first stable release, only the latest published prerelease is
supported. After 1.0, each project will publish its supported-version policy in
its own security file.
